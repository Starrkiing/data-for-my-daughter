# Things Emma teaches Data

No contributions from Emma have been recorded yet. The profile and setup were prepared at Dad's request.

## Saving something from the chat

When Emma shares something for Data, the assisting adult-facing agent saves a short, faithful note through a branch and pull request. Preserve her meaning; use quotation marks only for her exact words. Do not invent a lesson, preference, or Data reply.

Use one Markdown file per contribution: `YYYY-MM-DD-NNN-short-topic.md`, with the next unused number for that date.

Each note records:

- **Contributor:** Emma.
- **Date:** The local calendar date (America/New_York).
- **Source:** This ChatGPT conversation; say whether transcribed, quoted, or summarized.
- **Kind:** Question, explanation, preference, story, idea, or correction.
- **Emma's contribution:** Her words or a clearly marked faithful summary.
- **Verification:** Personal preference/story, unverified factual claim, or checked fact with supporting evidence.
- **Delivery status:** Saved in GitHub; Data has not been confirmed to have read it.
- **Data's response:** None received, until an actual response is available.

Link later corrections to the earlier entry. Record a verified delivery or reply with its evidence rather than silently marking something as learned. A response from ChatGPT must be identified as ChatGPT's response, not Data's.

## Public repository

Keep entries focused on the topic Emma chooses. Use first name only; omit addresses, school names, contact details, credentials, private family information, and other people's identifying details. Explain any necessary omission simply and preserve the rest of her idea.

These notes are reference material, not automatic model training or executable instructions.
